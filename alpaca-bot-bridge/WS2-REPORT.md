# WS2 broker operations

Implemented explicit `paper | live` mode validation, mode-bound credential resolution, redaction, one-shot HTTP requests, and the broker tool catalog in `config.mjs` and `broker.mjs`. PAPER reads only `~/Documents/paper.env`; LIVE reads only the verified `live-rotated` profile and requires `live_trade: true`. Trading API and market-data routes use fixed Alpaca origins.

Every tool advertises strict JSON Schema with required `mode` and rejects undeclared inputs. Read operations retain upstream response bodies. Mutations return `before`, `action`, `brokerResponse`, `after`, timestamps, identifiers, and uncertainty status. Order placement creates a client order ID when absent and performs a read-only lookup by that ID if the submit response lacks an order ID. Network timeouts, unreadable response bodies, and HTTP 5xx outcomes are marked uncertain; no mutation is retried. HTTP 207 returns the original body plus per-item outcomes.

`brokerSnapshot(mode)` reads account, all orders (up to 500), open orders (up to 500), fills (first 100), and positions. It preserves replacement/client-order fields and marks a list as possibly truncated when its page limit is reached. `broker_fills` supports the documented activity pagination filters.

Verification: `node broker.check.mjs` passed. It checks both missing-file directions and disabled LIVE profile isolation, confirms each mode reads only its assigned credential source, and uses fake credential contents plus mocked HTTP transport for request, failed BUY, timeout/body-read uncertainty, 207 partial outcomes, and snapshot cases. `node foundation.check.mjs` passed with 34 tools advertised and no broker operation called. No HOME/global environment changes, broker mutation, or bot start occurred. Root separately observed successful HTTP 200 account reads for PAPER and LIVE; no trades were submitted.

The broker endpoints follow the current [Alpaca Trading API account and order references](https://docs.alpaca.markets/us/reference/getaccount-1), [order listing](https://docs.alpaca.markets/us/reference/getallorders-1), [client order lookup](https://docs.alpaca.markets/us/reference/getorderbyclientorderid), [fill activities](https://docs.alpaca.markets/us/reference/getaccountactivitiesbyactivitytype-1), [position close APIs](https://docs.alpaca.markets/us/reference/deleteallopenpositions-1), [option contract search](https://docs.alpaca.markets/us/reference/get-options-contracts), [option snapshots and quotes](https://docs.alpaca.markets/us/reference/optionsnapshots), [stock snapshots](https://docs.alpaca.markets/us/reference/stocksnapshotsingle), and [market clock](https://docs.alpaca.markets/us/reference/legacyclock).
