# Lane 3: options quote decision trace

Root strategy events use `actionSource: "V5_AUTO"`. The trace envelope's `runId` scopes each run's `signalId`. The existing BUY client order ID is also recorded as `tradeSetId` and legacy-compatible `entrySetId`; each broker entry execution creates per-contract `tradeId` values in the form `<executionId>:<fill ordinal>`. Events retain applicable broker `clientOrderId` and `orderId` values. Continuity state now carries the signal and set IDs so restored fills keep the same lineage.

`spy_trade_evaluation` records the SPY source trade ID and timestamp, local receipt time, prior 30-second high/low, direction, eligibility, and reason. `signal_range` and `signal_accepted_for_selection` preserve the breakout context. `contract_candidate` records the ATM quote and, only when required by the existing rule, one directional OTM quote. Each includes bid, ask, midpoint, spread, source and receipt timestamps, eligibility, and a specific rejection reason. `entry_set` records the selected candidate rationale, frozen midpoint cap, submitted BUY limit, and the existing maximum quantity of three.

For each accepted usable option bid while a fill is open, `position_quote_accepted` and `lot_decision` are emitted in trace sequence order. The records include quote source/receipt times, elapsed age and exact 10,000 ms anchor eligibility, immutable anchor price/time/source, loss threshold and comparison, current downside floor, +$0.05 arm, +$0.08 rearm, and +$0.10 ceiling thresholds. `sell_latch` records the exact reason, triggering bid, comparison, threshold, and quote timestamps. `sell_request`, `sell_response`, `sell_order_update`, and `position_exit` link SELL client/order IDs to each entry fill. Confirmed exits include exact cents-derived premium change per share, the contract size when Alpaca supplied it, USD P&L when that size is known, and `tradeSetId` for set aggregation.

These events use the existing bounded, non-blocking trace queue. `observe` contains telemetry failures, and trace enablement or failure does not gate state transitions or broker decisions. The runnable check `node telemetry/decision-parity.check.mjs` compares signal, BUY, hold, SELL, and exit behavior with telemetry disabled, recording, and throwing. The repository parity check also compares against `/tmp/v5-consolidation-baseline` and verifies no trace drops or truncation in its representative lifecycle.
